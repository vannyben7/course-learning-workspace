# Course Learning Workspace 设计文档 v1

生成时间：2026-05-29  
状态：新一代系统设计基线

## 一句话定位

Course Learning Workspace 是一个围绕课程资料建立的阅读与学习工作台，帮助学生整理资料、阅读内容、记录学习笔记、形成理解、完成复习，并在原始资料可追溯的前提下主动提问和拓展。

## 设计出发点

高校对 AI 的核心担忧不是“学生能不能获得帮助”，而是“帮助是否替代了阅读、思考和理解”。因此新系统的重点不是展示 AI 能做什么，而是让学生的学习过程更清楚、更可追溯、更依赖课程资料本身。

系统默认不把知识完整喂给学生，而是提供阅读脚手架：

- 资料放在哪里。
- 当前学习单元和前后内容有什么关系。
- 阅读时应该关注哪些问题。
- 哪些术语、概念、段落值得停下来理解。
- 学生自己的笔记和 AI 辅助内容如何区分。
- 复习时如何回到原始资料验证理解。

## 核心流程

```text
Course Materials -> Reading -> Understanding -> Notes -> Review -> Explore
```

中文表达：

```text
课程资料 -> 阅读 -> 理解 -> 笔记 -> 复习 -> 拓展
```

这个流程刻意避开以最终表达成果为中心的产品叙事。系统帮助学生完成表达之前的学习过程；学生理解课堂内容之后如何在课堂讨论、考试、展示或作业中运用，是学生自己的后续行为。

## 兼容不同课程形态

底层抽象统一为 `Learning Unit`，界面显示可以按课程类型调整。

### 教材驱动课程

常见于中国本科课程：

- 一门课对应一本或几本教材。
- 每次课对应教材的一章或两章。
- 课件围绕教材展开。
- 课后补充文章、案例或习题。

界面可以显示为：

```text
课程 -> 章节 -> 课件 -> 补充阅读 -> 复习
```

### 周次驱动课程

常见于英国授课型硕士课程：

- 学期开始前给出 reading list。
- 每周有 lecture slides。
- 每周有 required / recommended readings。
- 课程学习依赖跨文章、案例和课堂主题的连接。

界面可以显示为：

```text
Course -> Week -> Slides -> Required readings -> Recommended readings -> Review
```

### Topic 驱动课程

适合模块化课程、短课、工作坊：

```text
Course -> Topic -> Materials -> Notes -> Review
```

## 信息架构

### Courses

管理课程、语言、资料文件夹、隐私和模型设置。

### Course Home

学生进入课程后的首页：

- 当前学习单元。
- 最近加入的资料。
- 继续阅读。
- 最近笔记。
- 今日复习。
- 需要重新理解的概念。

### Materials

课程资料库：

- 课件、PDF、文章、教材摘录、手册、课堂讲义。
- 文件状态、解析状态、跳过原因。
- 支持按 Week / Chapter / Topic 归类。

### Reader

核心阅读空间：

- 中间显示资料正文或预览。
- 右侧显示学习笔记和引用。
- 允许选中文本后触发解释、翻译、保存摘录、生成复习卡片。
- AI 默认不会在未触发时完整展开材料内容。

### Ask Materials

基于课程资料的问答：

- 只回答资料里能支持的内容。
- 每个实质性回答显示来源。
- 找不到依据时明确说明“课程资料中未找到”。
- 可以限定当前资料、当前学习单元或整个课程。

### Notes

学习笔记：

- 学生笔记优先。
- 原文摘录、AI 辅助解释、学生自己的理解分层标记。
- Markdown 存储，方便和 Obsidian 等本地笔记工具互通。

### Understanding

理解地图：

- 概念关系。
- 高频术语。
- 本节与之前学习单元的联系。
- 容易混淆的概念。

### Review

复习中心：

- 主动回忆卡片。
- 概念自测。
- 需要重新阅读的来源。
- 复习结果回到原始资料验证。

### Explore

拓展探索：

- 连接更多案例、背景和相关概念。
- 明确标记“课程外拓展”，不和课程资料混在一起。
- 学校可以关闭或限制这一功能。

## AI 行为原则

1. 课程资料优先。
2. 学生主动触发。
3. 引用可见。
4. 不确定就说不确定。
5. 翻译、解释和复习优先于完整代替阅读。
6. 外部拓展必须标记为课程外信息。
7. 云端模型需要明确同意。
8. 学校可以关闭云端模型、外部拓展和大段复制输出。

## 界面风格参考

### NotebookLM 可借鉴的部分

- 资料驱动。
- 基于来源回答。
- 回答可保存到笔记。
- 用户可选择资料范围。

### Obsidian 可借鉴的部分

- 本地 Markdown 笔记。
- 笔记之间的链接。
- 概念连接和图谱思维。
- 长期知识库而不是一次性聊天窗口。

### BBNote / 课堂笔记类软件可借鉴的部分

- 阅读、听课、记笔记和复习在同一个学习场景里。
- 翻译与解释靠近原文。
- 复习卡片和笔记联动。

## 第一版界面目标

第一版不追求完整后端能力，而是先让界面表达新定位：

- 左侧：课程与学习单元导航。
- 中间：Course Home / Reader / Notes / Review / Explore。
- 右侧：保守学习助手，只在学生主动触发时展开。
- 所有 AI 输出都要显示来源意识和边界意识。

## 暂不进入第一版的内容

- 多租户学校账号系统。
- 教务系统集成。
- 机构 SSO。
- 大规模课堂 analytics。
- 桌面安装包。
- 移动端 App。

这些能力应在 Docker-first 本地/小班试点稳定后再考虑。
